# Главный экран трекера расходов

## Результат

Заменить приветственную страницу полноценным трекером: транзакции по 10 записей на страницу, управление категориями, профиль и месячная сводка. Сохранить светлый интерфейс с зелёными акцентами и украинский язык приложения.

## Интерфейс и действия

- [x] Навигация: «Транзакції» (`/`) и «Категорії» (`/categories`). На компьютере — боковое меню, на телефоне — компактная верхняя навигация.
- [x] В шапке — профиль с инициалами. При открытии показывать имя, email и выход из аккаунта.
- [x] Над списком — выбор месяца и карточки «Доходи», «Витрати», «Баланс за місяць». По умолчанию выбран текущий месяц; сводка учитывает весь месяц независимо от фильтров списка.
- [x] Фильтры транзакций: месяц, доход/расход и категория. Хранить фильтры и номер страницы в URL; смена фильтра возвращает на первую страницу.
- [x] Список: дата, описание, категория с иконкой, тип, сумма в ₴ и действия. Сортировка — сначала новые, затем по ID для стабильного порядка. На телефоне отображать записи карточками.
- [x] Пагинация: 10 записей, номера страниц, переход назад/вперёд и счётчик записей. После удаления последней записи страницы переходить на предыдущую доступную.
- [x] Добавление и редактирование транзакции — в диалоге: тип, положительная сумма, категория, дата и время, необязательное описание. Принимать запятую в сумме, отправлять API десятичную строку.
- [x] Удаление — с подтверждением. После успешного изменения обновлять список и сводку; при ошибке сохранять заполненную форму.
- [x] Раздел категорий: список, создание и редактирование названия, цвета и иконки; удаление с подтверждением. Для занятой категории показывать понятное сообщение об ограничении.
- [x] Если категорий нет, предложить сначала создать категорию. Предусмотреть состояния загрузки, отсутствия операций, пустого результата фильтрации и ошибки с повторной попыткой.

## Реализация и контракты

- [x] Соблюдать FSD: композиция экранов в `views`, общий каркас в `widgets`, действия в `features`, модели и чтение данных в `entities`. Использовать shadcn/ui и Lucide.
- [x] Страницы и начальные чтения выполнять на сервере; формы и диалоги оставить небольшими клиентскими компонентами.
- [x] Добавить серверную пагинацию к `GET /api/transactions`: необязательный положительный целочисленный `page`; при его наличии возвращать `{ items, total, page, pageSize: 10 }`. Без `page` сохранить существующий ответ-массив для совместимости.
- [x] Выполнять фильтрацию и подсчёт общего количества на сервере с одинаковыми условиями и ограничением по пользователю. Для страницы за пределами списка возвращать пустой `items`; интерфейс переводит на последнюю доступную.
- [x] Существующие контракты CRUD и месячной сводки сохранить. Названия категорий сопоставлять по `categoryId`.
- [x] Из браузера отправлять изменения через same-origin Next.js route handlers. Bearer-токен читать только из HttpOnly cookie на сервере; проверять Origin для изменений, переводить ошибки на украинский, не кэшировать персональные ответы.
- [x] При истечении сессии направлять на вход; сетевые ошибки показывать как временную недоступность.
- [x] Обновить README с контрактом пагинации и сценариями ручной проверки. Изменения схемы БД и переменных окружения не требуются.

## Проверка

- [x] API-тесты: страницы для 0, 10, 11 и 21 записи; количество с фильтрами; одинаковые даты; некорректный `page`; изоляция пользователей; совместимость запроса без пагинации.
- [ ] Проверить создание, редактирование и удаление транзакций и категорий, запрет удаления занятой категории, обновление сводки и переход после удаления последней записи страницы.
- [ ] Проверить границы месяцев, десятичные суммы, сохранение фильтров при перезагрузке и переходах назад/вперёд, истечение сессии и недоступность API.
- [x] Запустить API-тесты, lint, typecheck, build и проверку форматирования.
- [ ] Проверить интерфейс на ширинах 375, 768 и 1440 px, управление клавиатурой, фокус в диалогах и отсутствие горизонтальной прокрутки; подготовить скриншоты для PR.

## Принятые настройки

- Полное управление транзакциями и категориями; профиль только для просмотра и выхода.
- Одна валюта — гривна. Без графиков, бюджетов и мультивалютности на этом этапе.
- Месяцы и отображение дат используют UTC согласно текущему контракту сводки; явно обозначить это возле выбора периода. Ввод локальных даты и времени преобразовывать в ISO с часовым поясом.
- Работать в отдельной feature-ветке; существующие пользовательские изменения сохранить.
