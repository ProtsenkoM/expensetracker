# Модуль транзакцій

## Підсумок

Додати backend-модуль `TransactionsModule` за зразком `apps/api/src/categories`: controller → service → repository. Реалізувати облік доходів і витрат, фільтрацію та місячний підсумок. Frontend і нові залежності не входять у задачу.

## Модель і міграція

- [x] Додати `Transaction`: UUID `id`, `amount Decimal(18,2)`, enum `TransactionType` зі значеннями `Income`, `Expense`, nullable `description`, `date`, UUID `categoryId`, UUID `userId`, `createdAt` з `now()`.
- [x] Додати зворотні зв’язки `transactions` у `User` і `Category`.
- [x] Видалення користувача каскадно видаляє його транзакції. Видалення категорії з транзакціями заборонене через `onDelete: Restrict`; наявний endpoint категорій повертає `409 Conflict` при відповідному порушенні зовнішнього ключа.
- [x] Додати індекси `[userId, date]` та `[categoryId]`.
- [x] Створити й застосувати локальну міграцію `add-transactions` через `npm run db:migrate -- --name add-transactions`, згенерувати Prisma Client. Не змінювати попередні міграції.

## Контракти й поведінка API

Підключити модуль у `AppModule`. Усі маршрути використовують чинну JWT-авторизацію та префікс `/api`.

| Метод і маршрут | Поведінка |
|---|---|
| `POST /api/transactions` | Створення, `201`, повертає транзакцію |
| `GET /api/transactions` | Масив із фільтрами `dateFrom`, `dateTo`, `type`, `categoryId` |
| `GET /api/transactions/summary` | Обов’язкові `month`, `year`; повертає `totalIncome`, `totalExpense`, `balance` |
| `GET /api/transactions/:id` | Одна транзакція |
| `PATCH /api/transactions/:id` | Часткове оновлення, повертає транзакцію |
| `DELETE /api/transactions/:id` | Видалення, `204` без тіла |

- [x] Суми приймати як додатні десяткові рядки, максимум 16 цифр до крапки та дві після; відхиляти нуль, від’ємні значення й експоненційний запис. Обчислювати через Prisma Decimal, повертати суми рядками з двома десятковими знаками.
- [x] Для створення обов’язкові `amount`, `type`, `date`, `categoryId`; `description` необов’язковий або `null`. PATCH приймає ці самі поля, але вимагає хоча б одне; `null` дозволений лише для опису.
- [x] Використати `class-validator`, чинний `ValidationPipe` і UUID-валідацію. Заборонити сторонні поля, зокрема `userId`, `id`, `createdAt`.
- [x] Приймати дати як ISO 8601 із часовим поясом. Межі списку включні; `dateFrom > dateTo` повертає `400`. Фільтри поєднуються через AND; порядок — `date DESC`, потім `id DESC`. Пагінацію не додавати.
- [x] `month` — ціле число 1–12, `year` — 1–9999. Підсумок рахувати за інтервалом від початку місяця UTC включно до початку наступного місяця виключно. Баланс = доходи − витрати; порожній місяць повертає `"0.00"` для всіх сум.
- [x] Кожен запит обмежувати поточним `userId` із JWT. Чужі та відсутні транзакції повертати як `404`; створення або перенесення в чужу чи відсутню категорію — також `404`.
- [x] Перевірку власника категорії та запис транзакції виконувати атомарно; помилки конкурентного видалення категорії перетворювати на контрольовану відповідь без `500`.
- [x] Оголосити маршрут `summary` перед `:id`. Відповіді транзакцій містять поля моделі без вкладених об’єктів користувача чи категорії.
- [x] Оновити README прикладами запитів, форматом сум, правилами дат і видалення категорій.

## Зафіксовані припущення

- Одна спільна валюта без конвертації; поле валюти не додається.
- Фінансові суми — десяткові рядки; підсумок містить лише загальні суми.
- Календарні розрахунки виконуються в UTC.
- UI, Next.js route handlers і зміни авторизації не потрібні.
