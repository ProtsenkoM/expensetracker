# Категорії витрат: модель і CRUD API

## Загальний підхід

Додати модуль `Categories` у NestJS API з контролером, сервісом і репозиторієм. Використати наявні глобальні `JwtAuthGuard` та `ValidationPipe` з `class-validator`. Фронтенд у цю зміну не входить.

## Модель і валідація

- Додати Prisma-модель `Category`: `id` — UUID із автоматичною генерацією, `name`, `color`, `icon`, `userId` — UUID.
- Додати зв’язок із `User`, індекс за `userId` та каскадне видалення категорій під час видалення користувача. Підготувати міграцію.
- `name`: рядок, обрізати пробіли по краях, від 1 до 100 символів.
- `color`: рядок у форматі `#RRGGBB`, перевіряти HEX через `class-validator`.
- `icon`: текстовий ключ від 1 до 100 символів після обрізання пробілів, наприклад `shopping-cart`; без перевірки за каталогом бібліотеки.
- Однакові назви категорій дозволені.
- DTO створення вимагає всі три поля. DTO оновлення дозволяє передати будь-яку їх частину; `null` і порожнє оновлення повертають `400`.
- `id` і `userId` не приймаються в тілі запиту; власник визначається через `@CurrentUser()`.

## API та доступ

| Метод | Endpoint | Результат |
| --- | --- | --- |
| POST | `/api/categories` | Створення категорії, `201` |
| GET | `/api/categories` | Масив категорій поточного користувача, `200` |
| PATCH | `/api/categories/:id` | Часткове оновлення, `200` |
| DELETE | `/api/categories/:id` | Видалення, `204` без тіла |

- Створення й оновлення повертають `{ id, name, color, icon, userId }`.
- Список без пагінації, відсортований за `name`, потім `id`; за відсутності категорій — `[]`.
- Сервіс надає методи `create`, `findAll`, `update`, `remove`; кожен отримує ID поточного користувача.
- Оновлення та видалення фільтруються одночасно за `id` і `userId` на рівні запиту до БД. Відсутня або чужа категорія повертає `404`.
- Параметр `:id` перевіряється через `ParseUUIDPipe`; некоректний UUID повертає `400`.
- Усі endpoint захищені наявним глобальним guard; без чинного токена — `401`. Новий guard не потрібен.

## Перевірка

- Додати тести на створення, отримання лише власних категорій, часткове оновлення та видалення.
- Перевірити ізоляцію двох користувачів: чужа категорія недоступна для зміни чи видалення.
- Перевірити DTO: некоректний HEX, порожнє ім’я, перевищення довжини, `null`, порожній PATCH та сторонні поля.
- Використати наявний `node:test`; перевірити HTTP-сценарії з реальною БД і JWT.
- Запустити тести, lint, typecheck, build та перевірку форматування. Міграцію перевірити на локальній БД; згенерований Prisma Client не комітити.
